# WP-AA1 – Architecture Alignment

## Outcome

WP-AA1 aligns the vital runtime with `ARCHITECTURE_FREEZE_v0.6.0.md` without adding
clinical behavior. `VitalSignState` is the single writable vital-sign source.

```text
Clinical Effect
      |
      v
PatientProcess -> PatientVitalContributor
      |
      v
VitalSignRuntimeResolver -> VitalSignEngine
      |
      v
RuntimeAggregationPipeline -> canonical RuntimeState
      |
      +-> frozen compatibility projection
```

## Canonical and compatibility fields

Canonical:

- `RuntimeState.vitalSignState`.

Read-only projections generated by `projectVitalSignState()`:

- `targetVitals`;
- `displayedVitals`;
- `mapCalculated`;
- `gcsTarget`.

The projection is regenerated after cloning at the public ScenarioEngine boundary.
It has no independent update path.

## Manual override

Vital overrides are converted to deterministic `MANUAL_OVERRIDE` contributors and
resolved by the same VitalSignEngine as PatientProcess contributors. They update
current and target readings, trends, derived values, attribution, events, and all
compatibility projections in one pass. Aggregation handles only non-vital overrides.

## Compatibility

Pre-freeze ProcessOutput vital fields remain supported only by
`LegacyVitalContributorAdapter`. The adapter produces typed contributors; it does
not calculate displayed monitor values. `RuntimeAggregationPipeline` no longer
imports or invokes VitalSignEngine. Its historical export path re-exports the
aligned pipeline solely for unchanged callers and Golden tests.
